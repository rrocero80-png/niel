# Campus Facility Reservation Monitoring: Streamlit Deployment

Predicts **cancellation / no-show** for facility reservations and supports a **facility administrator review** workflow. Predictions are decision support only; they never authorise automatic rejection of a reservation or denial of student services.

> **Status of data/model:** this repo ships a **synthetic dataset** and a **stand-in RandomForest pipeline** (`train_model.py`) so the app runs end to end. Replace them with your midterm outputs (see "Swap in your midterm work").

## Structure
```
app.py                       navigation + page wiring
modules/config.py            target, features, categories, thresholds (edit to match midterm)
modules/data_processing.py   CSV load, schema validation, null/duplicate summary
modules/exploratory_analysis.py   stats + Plotly charts
modules/prediction.py        load pipeline, one-row input, predict, limitations
modules/dashboard.py         KPIs, risk queue, interpretations
modules/system_design.py     requirements, actors, workflow text
models/trained_model.joblib  fitted preprocessing + model pipeline
models/model_metadata.json   version, metrics, features
assets/use_case_diagram.png  generated by make_diagram.py
data/sample_reservations.csv synthetic sample
```

## Swap in your midterm work
1. In your notebook, fit a single `sklearn.pipeline.Pipeline` (preprocessing + model) on **booking-time features only** and run `joblib.dump(pipe, "models/trained_model.joblib")`.
2. Put your test metrics in `models/model_metadata.json` (same keys: `model_version`, `model_type`, `trained_at`, `data_source`, `target`, `features`, `metrics` with accuracy, precision, recall, f1, roc_auc, confusion_matrix, test_rows).
3. Edit `modules/config.py`: `TARGET`, `CATEGORICAL`, `NUMERIC`, `CATEGORY_VALUES`, `NUMERIC_BOUNDS`, `LEAKAGE_COLUMNS`.
4. Use the **same scikit-learn version** locally and in `requirements.txt` (pin it, e.g. `scikit-learn==1.x.y`), or the joblib file may fail to load on Streamlit Cloud.
5. Re-run `python make_diagram.py` if you change use cases; update `modules/system_design.py` text to match what you really implemented.
6. Copy your original midterm `.ipynb` into the repo for submission.

## Run locally
```
pip install -r requirements.txt
python train_model.py      # only if you want to regenerate the stand-in model/data
python make_diagram.py
streamlit run app.py
```

## Deploy (Streamlit Community Cloud)
1. Push the repo to GitHub (no passwords, no real student records).
2. Go to https://share.streamlit.io, sign in, **Create app**, pick repo + branch, entry point `app.py`, **Deploy**.
3. If the build fails, open **Manage app → Logs** (usual causes: unpinned/mismatched scikit-learn, missing file path).

## Test checklist
| Test | Expected |
|---|---|
| Upload valid CSV | Preview, null/duplicate counts, no errors |
| Missing column / empty file / header-only | Clear error message, nothing crashes |
| Extra leakage column (e.g. `checked_in`) | Warning, column dropped |
| Valid prediction | Class, probability, band, follow-up, timestamp, model version |
| Invalid prediction (hour 3, cancellations > reservations) | Error messages, no prediction |
| Prediction vs midterm notebook on same rows | Same probabilities |
| All pages | No placeholder text |

Logic tested in the build environment: schema checks, empty/bad files, leakage drop, input validation, single vs batch prediction consistency. UI pages must be checked after `streamlit run`.

## Limitations
- Stand-in model on synthetic data is not predictive of real campus behaviour.
- Decision log is held in session memory; download it as CSV (no database).
- Risk thresholds (60% / 35%) are illustrative; set them with administrators.
